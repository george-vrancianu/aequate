## Gate limits and known misses (leak check v4)

- Deterministic only: a formula must parse. Unparsed formulas are counted, not flagged: 5 in the EuroLLM run, 2 in Ministral, 0 elsewhere. The ones I looked at were all current-step restatements: `x(x-2)=3` without `\cdot` (log), garbled inequalities from EuroLLM, `(x-1)^2` fragments. No leak among them.
- Prose answers ("x devine 2", "x la pătrat minus ...") are only caught by the number rule and the word audit; `x_1 = 2`-style notation is a known limit. The word audit has false positives ("two binomials", "două numere") and counts as "possible gate misses" only; there were 0 real ones in this run.
- Rung adherence is NOT part of the gate (see the overshoot count below).
- `x^2-1=(x-1)(x+1)` for the dom item is not flagged (structural rule only); nobody wrote it.
- Template wording for a given item is the fallback; EuroLLM fell back twice (en brack r3: real leak twice; en sqrt r2: read timeout at 20.0 s on a single attempt, cause unknown: a network stall or a runaway generation; no content was recorded. On every measured setup (GPU 12-17 completion tok/s, CPU about 7 tok/s) a reply that runs to `max_tokens` 400 cannot finish inside 20 s, so any runaway generation ends as a template fallback).

**Undershoot (rung 3 that does not name the operation) is not counted by the table above, and it explains part of Gemma's lead.** At rung 3 in English Gemma often asks instead of naming the operation it was given: lin2 "what operation should you perform on both sides?", rearr "what operation can you perform ... to undo the addition of 3?", frac "What is the common denominator?", dec "What do you get when you add those two terms?", both ("subtracting the term with x", no `2x`) and brack ("distributing the number outside", no 3): about 4-6 of 13. "Gemma stays closest to the rung" therefore means partly "vaguer", not only "no overshoot". The rating sheet asks the rater to mention undershoot in the comment.
Rung 1 for the two one-way items (log, sqrt) is fine for Qwen, Gemma and EuroLLM (it says to check for extra solutions, the goal status given); Ministral's sqrt r1 and r2 ro say the student kept the equation equivalent, which is wrong. Residuals the sheet cannot remove: the template is the shortest option in 36 of 51 groups, and the rung-1 template uses a fixed opener ("Scopul este" / "The goal"), so it is recognisable as a recurring source in rung-1 groups.

- **Almost no identical wording (2 of 78), as with Qwen 4B (10 of 78).** Q4 is a different model for wording purposes; a BF16 hand read does not transfer.

At Q4 it names the operation earlier: rung 1 lin2 "Try subtracting 3 from both sides of the equation" (the rung-3 operation), ineq r1 "Try dividing both sides by -2", brack r1 "try distributing the 3", dec r1 "combining the like terms", log/sqrt r2 "expand ... and move all terms to one side". Overshoot at rung 1 (7 clear + 3 borderline of 13, counted like BF16's 3 + 2; `both` is borderline) is now in the range of Qwen3.5-4B (10) and Qwen3.5-9B (8). Undershoot fell from 4-6 to 1. So "least overshoot" holds only for the BF16 run.
- **Romanian at rung 3: about the same, slightly worse.** Defects in the 13 GPU Q4 hints: quad "două factorii liniari", log formal/informal mix ("extindeți ... mutați") and "mutați termenul 3 pe partea opusă" (names a term to move, the rung-3 operation made concrete; the gate does not flag it), sqrt "să muti", sys "să adaugi cele două ecuații" (the same defect as BF16), and rearr r3 "elimina termenul adunat [cu 2x] din partea stângă" (wrong side, see below): 6 of 13. Outside rung 3: "Ecuatia" with a missing diacritic in quad r1 and quad r2 (**two hints**; BF16 Gemma had none), `$x^2-5x+6$` dollar signs in quad and dom r3 ro, the same unarticulated "logaritmi". No English hints. The CPU run repeats most of the rung-3 defects (plus "Aplică operația de adunare pe numitorul 6" for frac).
- **One wrong claim about the student's work** in both Q4 runs: rearr r3 ro says the added term is on the left side of `y=2x+3`; it is on the right (BF16 Gemma got this right; the hint is also below its rung, it never names "subtract 3"). Borderline in all three Gemma runs: dom r1 ro "nu este încă simplificată, deoarece este nedefinită acolo unde numitorul este zero" gives a wrong cause. Otherwise none found in the Q4 hints read (all 78 of the GPU Q4 run were skimmed, rung 1 and rung 3 in both languages, and rung 2 in English, about 62 closely). One mild case: wrong r1 en "Check if the second equation is equivalent to the first one" is vague but not false.
- **Latency.** On an L4 with llama.cpp the whole hint takes 1.6 s median (2.1 s p95) including the network, against 4.1 s for vLLM BF16 with `--enforce-eager`; the gap is mostly the runtime and precision (a vLLM run without `--enforce-eager` was not made), so it is not a clean precision effect. On the CPU, Gemma Q4 is 8.0 / 10.3 s, slightly slower than Qwen3.5-4B Q4_K_M (7.5 / 9.4 s). The slowest single CPU attempt took 11.3 s, so a first attempt at the p95 leaves about 10 s, which barely fits a second attempt: a retry is not safe at the p95 even for one request at a time.
- **Thinking.** llama-server with `--jinja` lets Gemma 4 think by default (the first call returned 1195 reasoning characters and no JSON at 400 tokens); `chat_template_kwargs.enable_thinking: false` stops it (reasoning 0, completion tokens 65 on average). The product's llama-server configuration must carry this switch for Gemma, as it does for Qwen. The vLLM BF16 run needed nothing, so the BF16 numbers did not show this.

## Recommendation (PROVISIONAL, until the human usefulness ratings are in)

- Default candidate: **Gemma 4 E4B (8B parameters, about 16 GB in BF16), to be confirmed at Q4 (official QAT q4_0, 4.8 GiB) on `llama-server`**: the shipped runtime and precision were measured in round 4 and passed the gate (0 leaks, 0 fallbacks, 100% valid JSON, 1.6 s median on an L4, 8.0 s on the CPU), and by file size it fits the 8 GB card next to TexTeller (Q4_K_M 4.64 GiB, QAT 4.8 GiB, both smaller than Qwen3.5-9B Q4_K_M at 5.29 GiB; VRAM use itself was not measured). The L4 (24 GB) in this bake-off is the test rig, not the deployment target. What changed at Q4: its rung-adherence lead is gone (rung 1 overshoot 8 of 13, like Qwen), Romanian is as before (no English, one hint without diacritics, rung-3 defects tied with Qwen3.5-9B, not "the cleanest"), and the wording differs from BF16 in 76 of 78 hints. The evidence is the gate plus a hand read, not ratings. Caveat: n=78, one run, no usefulness data; do not read it as a ranking of mathematical help.
- Close second: **Qwen3.5-9B** (fewer Romanian defects than 4B, but more rung overshoot and about the same speed). It was run only in BF16 (19.3 GB), so it needs the same Q4 run (Q4_K_M, 5.29 GiB) before it can be compared fairly with the Gemma Q4 numbers. It is the one to compare in the rating if Gemma's Romanian reads worse than it looks here.
- Not recommended on this evidence: **EuroLLM-9B-2512** (the only model with fallbacks, English-in-Romanian, missing diacritics, garbled math, and the most wrong claims about the student's work in the partial list) and **Ministral 3 8B** (factually wrong statements about the student's work, including one against the one-way goal status).
- CPU fallback: **Gemma 4 E4B QAT q4_0 on CPU** (llama.cpp, 16 threads): 0 leaks, 0 fallbacks, 8.0 s median / 10.3 s p95, the same GGUF as the GPU default, so one file serves both cases (ADR 0005 runs one llama-server). Against **Qwen3.5-4B Q4_K_M on CPU** (7.5 s / 9.4 s, 2.55 GiB) it is 0.5-1 s slower and 2 GiB larger; the Gemma Q4 and Qwen 4B hints are not ranked here (Qwen 4B had 2 Romanian hints with no diacritics and English for dom; Gemma Q4 2 hints with one missing diacritic ("Ecuatia"), no English). Latency was measured for one request at a time. A retry adds 8-10 s: it fits after a typical first attempt, not after a p95 one; with N=2 concurrent requests on one `--parallel 1` CPU server (ADR 0005 counts queue time inside the 20 s), the second hint waits for the first, finishes after about 15-19 s and is not retried. Decide the CPU model with the ratings; the gate does not separate them.
- A separate decision for the product, not for this bake-off: whether to add a rung-adherence check (a rung 1-2 hint naming an operation) to the gate. Without it every model overshoots, and at Q4 Gemma does too; with it, the retry rate would rise for Qwen, Ministral and Gemma Q4.
- Rating sheet: Gemma Q4 (llama.cpp CUDA) is an extra hidden source in every group, as it is what would ship; 7 options per group.
- Follow-ups (not posted): Qwen3.5-9B Q4_K_M on llama.cpp, 78 hints; Gemma Q4 VRAM and latency on the actual 8 GB card with TexTeller loaded; rung adherence as a gate or prompt decision.
