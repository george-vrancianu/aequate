## 0. What S7b is

- Input: the UNEVALUATED parse of before and after (same parser path as the harness: `check_line_raw`, strict ANTLR + guards; no sympify/eval). For an equation both sides count.
- Output per step: SAME domain / DOMAIN CHANGED (with `excluded` = defined before but not after, `added` = defined after but not before) / UNDECIDED.
- Real convention: see the header of `domain.py` (rational power p/q in lowest terms: q even needs base >= 0, > 0 if p < 0; q odd is the REAL root, defined for all real base; x^0 needs x != 0; x^y with symbolic y, unlisted functions, log with a base: UNDECIDED).
- Representation: a conjunction of atomic constraints (`e != 0`, `e >= 0`, `e > 0`), not a set over R^n. Univariate atoms are solved per variable into intervals plus excluded points with canonical periodic classes (this is the `ImageSet` / union canonicalisation: `pi/2 + k*pi` equals `pi/2 + 2k*pi` U `3pi/2 + 2k*pi`). Multivariate atoms, and univariate inequalities with trig (SymPy's `solveset(sin(x) > 0)` returns one period only), stay symbolic and are compared by canonical key. Any difference or sameness is then cross-checked at exact grid points; a differing point proves CHANGED; a claimed difference that no point confirms, or opaque constraints that differ with no differing point, are UNDECIDED.

### 5.1 Facts from the run

"Named correctly" for the odd-root TPs (D66, D69, D79, D83, D84, D91, D92; D93 has an irrational exponent and is not an odd-root form) means the exact witness lies in the labelled set; they carry no solved set (see the next bullets). The recall drop is the price of the B1' and B1'' fixes. The first version (commit bb8505c) scored 65 steps at 100% / 98% but had three defects found by the reviewer; D66-D92 are probes written from those failures and the families around them, therefore regression cases, not an independent sample. Timing is in section 3 (it varies per run).
- The 20 original steps: S7 (unchanged) 17 correct / 2 partial / 0 wrong / 1 undecided; S7b 18 / 2 / 0 / 0. The only difference is #13 (`y=2x+3` -> `x=(y-3)/2`, two variables), which S7 left undecided and S7b settles as EQ. The 2 partial are the one-way steps #14, #15, which both strategies reject as plain NEQ at the numeric stage, exactly as before. The three domain traps (#7, #17, #19) are flagged with the same named values as S7 (`x = 1`, `x = 1`, `x = pi/2 + k*pi`).
- Domain representation: a conjunction of atomic constraints (`e != 0`, `e >= 0`, `e > 0`) per side, solved per variable where possible, not a set over R^n. Reasons: (1) SymPy has no usable R^n set type for this: `ProductSet` only expresses separable domains, and a constraint like `x*y >= 0` or `x != y` is not a product (the first version of this question, `sqrt(x)*sqrt(y) -> sqrt(x*y)`, needs exactly such a constraint); (2) the constraints themselves are what an amber message needs ("only if x - y != 0"), and the run prints them when the step changes them (column "constraint diff"); (3) comparing two conjunctions splits cleanly into an exact part (one-variable atoms, solved into intervals plus excluded points) and an opaque part (compared by canonical key), and anything that falls between is refuted by a point or reported as undecided. Cost: sameness of two different-looking opaque constraints cannot be proved (D54, D65), and the exact set of a multi-variable change is not computed, only a witness point plus the changed constraints.
- Canonical comparison of `ImageSet`s and unions: periodic exclusion sets are decoded to classes `{(q + c*k)*pi + rest}` and reduced to the minimal period, so equal sets written differently compare equal and differences are named. Evidence: D10 (`1+cos(2x)=0` vs `cos(x)=0`), D57 (`tan x + cot x` vs `1/(sin x cos x)`: union of two sets vs sets from a product), D59 (half-angle: `sin(x/2)=0` U `cos(x/2)=0` equals `sin x=0`), D9 / D58 (`x = k*pi/2` as one class vs union of two ImageSets), D11 (named difference `pi/2 + k*pi` out of a union of three classes). All SAME where equal, none false-flagged. This is the failure the CAS spike warned about (equal sets written as different ImageSets flagged as "domain changed"); it did not occur on any step here.
- SymPy defect found and guarded: `solveset(sin(x) > 0, x, Reals)` returns `Interval.open(0, pi)` (one period, not the whole solution set). Inequalities containing sin/cos/tan/cot/sec/csc are therefore never solved; they stay opaque (D51, D52, D53, D63, D54, D65). Equations (`!= 0` atoms) with trig return complete ImageSets and are used.
- A bug found by a stress probe, fixed, kept as D63: when an opaque constraint is present (here `sin x >= 0`), the per-variable exclusion set of a `!= 0` atom (`cos x != 0`, i.e. `pi/2 + k*pi`) is only a superset of the true difference (3*pi/2 + 2k*pi is already outside `sin x >= 0`). S7b now names such a step by a witness point only and treats the per-variable sets as hints.
- The pointwise check is a second line of defence in both directions: it can only prove CHANGED (a differing exact point is a proof), and a symbolic difference that no point confirms is reported UNDECIDED. In this run it never contradicted the symbolic result.
- Multi-variable results are named by one exact witness point (plus, for opaque atoms, the constraints only before / only after). The check "named correctly" for those steps compares the witness against a label predicate I wrote, so it verifies one point in the region, not the whole region.
- Real-power convention (stated in `domain.py`): odd roots are real (x^(2/3) and `(x^(1/3))^2` are defined on all R), x^0 needs x != 0, `x^y` with symbolic y, `log` with a base and unlisted functions are UNDECIDED. D30, D31, D34 and D66-D69 depend on the odd-root convention; with SymPy's principal branch they would get different answers. The first version applied the convention only when collecting constraints, while `solveset` and the pointwise refuter used SymPy's mixed branches: `solveset(x**(1/3)+3 >= 0)` returned the FiniteSet {-27}, `solveset(x**(2/3) > 0)` the principal-branch (0, oo), and `(-2)**(1/3)` counted as undefined. That gave a false SAME on `ln(x^(2/3)) -> (2/3) ln x`, false amber on `1/cbrt(x) -> x^(-1/3)` and a wrong named set on `sqrt(x^(1/3)+3)^2`. Fix: every constraint expression is rewritten, before normalising, solving and evaluating, to the real-root form `(sign(b)*Abs(b)**(1/q))**p` for `b**(p/q)` with q odd, so all three parts follow one convention (D66-D69 now correct). Decimal exponents are their Rational value (`x^{0,5}` = x^(1/2), `x^{2.0}` = x^2); the first version treated a Float exponent as irrational (base > 0) and flagged D70/D71-type steps falsely. Only a genuinely irrational constant exponent needs base > 0.
- Defect signal: when the symbolic comparison says SAME but a grid point disagrees, the verdict is now UNDECIDED (logged in the `why` column), not CHANGED: the refuter and the solver use separate evaluation code, so a conflict means a bug in one of them. It did not occur in this run.

### 5.2 Limits of this evidence

- The labels, the rules and the stress steps were written by the same agent; the stress tier was added after seeing a clean first run, and the D63 bug came from that probing. 0 FP / 0 FN is therefore evidence on 92 chosen steps, not an error rate. A different author would probably find more undecided and some wrong ones.
- Rule coverage is exactly the whitelist: Add, Mul, Pow (rational exponents, integer exponents), exp, log (natural), sin, cos, tan, cot, sec, csc, asin, acos, atan, Abs, sinh, cosh, tanh, constants. Everything else (asec/acsc/acot, floor, factorials, Piecewise, symbolic exponents, complex numbers) is UNDECIDED by design.
- Equations: both sides are treated as one domain; only two equation steps of the original 20 exercise this. Systems and inequalities as steps are not covered.
- The grid has at most 40 / 11 / 6 values per variable for 1 / 2 / 3 variables and a 1500 point budget; it is a refuter, not a proof of sameness. Sameness rests on the symbolic comparison (equal one-variable sets and equal opaque keys), which relies on SymPy's `solveset` for polynomial, root and log atoms being correct. No independent check of `solveset` beyond the grid exists, and `solveset` has now been caught being wrong on this input class twice (`solveset(x**(1/3)+3 >= 0, x, Reals)` = {-27} in round 1, bypassed by the real-root rewrite; `Abs(x)**(2/3)` forms in round 2, which the rewrite itself creates; both found by the reviewer, neither fixed in SymPy). The round-2 guard samples the solver on Abs/sign/non-integer-power atoms but cannot confirm it (round 3); the odd-root forms are therefore excluded from SAME and from named sets, and other atom kinds (plain polynomials, logs, sqrt atoms) are trusted without an independent check. Rational exponents with an odd denominator and decimal exponents appear in only D30-D34 and D66-D93 of the labelled set, and D66-D93 were written from the reviewer's failures or the family around them. Not covered: the x1-x7 extra trig identity checks of the original harness were not run through S7b. The `Dset` per-variable report for several variables with only one-variable atoms is a disjunction (the output now says OR), not a conjunction.
- Parse guards are untouched and reject some natural inputs (`x(x+1)` implicit call syntax: D6 and D22 were first rejected as "undeclared function x" and rewritten with `\cdot`).
- Timing: all steps are small; nothing here stresses the 2 s timeout. The slowest are trig steps with several constraints (see section 3). Deeper nesting or three or more variables with trig would grow the solver and grid cost; not measured.

### 5.3 Recommendations (not facts)

- Is S7b reliable enough to drive an amber "only if x != a" verdict? Yes for the shape it covers (whitelisted rules, real-root convention for odd denominators, decimal exponents read as their rational value), with these limits: (0) S7b gives NO green on odd-root / rational-exponent forms with an odd denominator and an even numerator, written as x^(2/3), x^(4/3), x^(2/5), ... (any odd-denominator exponent whose atom has Abs/sign after the rewrite is covered by the rule, odd numerators included, e.g. D68 with x^(1/3), x^(2/3)) inside an inequality or `!= 0` constraint that survives normalisation: SAME is UNDECIDED ("can't check") there, because `solveset` is wrong on them and sampling cannot confirm it (D87-D90 are false greens that the sampling guard alone let through). Amber is possible only through an exact witness point (the verdict then carries the witness and the constraint list, not a solved set). Do not promise to decide these steps; a substitution `t = x^(1/q)` fallback is the way to recover them; (1) only when the verdict is CHANGED from the whitelist rules above; any UNDECIDED, unsupported node or timeout must show as "can't check", never green; (2) for one variable with solved sets, the named set (finite points, intervals, periodic classes) is exact as far as `solveset` is right (it was wrong on odd-root forms, see 5.1/5.2; those forms never yield a SAME or a named set any more; other kinds of atoms are not cross-checked) and can be shown as "only if x != 1" or "only if x is not pi/2 + k*pi"; (3) for several variables, or with trig inequalities, show the assumption as the constraint list ("only if x - y != 0"; the list now diffs all normalised constraints, not only the opaque ones; constraint lists show the INTERNAL real-root form, e.g. `Abs(x)**(1/3)*sign(x) > 0`, so a printer back to `x^(1/3)` is needed before any UI use), not as a computed region: the exact region is not computed and the witness is a single point; (4) a SAME verdict should be shown green only together with the numeric/solution-set verdict, and "SAME domain" with opaque trig inequalities is only as strong as the key match (it proves nothing when the keys differ: that is UNDECIDED, which is the safe side).
- Treat the amber text as an assumption to be checked by the student, not a proof that the step is correct elsewhere; S7b says nothing about whether the rewrite is valid (it runs after the numeric check, as S7 did).
- If a decision needs more than this: a second author for the label set, a larger multi-variable set with trig, and an independent `solveset` cross-check for ALL atoms (the guard here covers only Abs/sign/non-integer-power atoms, by sampling, and sampling can only refute; interval arithmetic over the claimed difference would be stronger) before relying on SAME, and a substitution fallback for odd-root forms.
- Policy questions for "Decide CAS equivalence semantics": the odd-root convention (real vs principal) changes verdicts on rational-exponent steps; `x^y` with symbolic y is undecided and may need a positive-base assumption; whether `sqrt(x)*sqrt(y) -> sqrt(x*y)`-type steps (valid for positive values, domain-enlarging otherwise) show amber with "only if x >= 0 and y >= 0".
